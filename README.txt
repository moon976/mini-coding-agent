mini-coding-agent —— 从零手写的编程智能体

【一、这是什么】
命令行程序，另附网页界面。你用自然语言下任务，它把任务交给大模型，模型说出"我要读
这个文件""我要执行这条命令"，程序在本地真的去做，把结果交回模型继续
判断，循环往复直到完成。

对话历史管理、工具定义与执行、输出解析、循环终止、错误处理全部自研，
未使用任何 agent 框架或 SDK，仅在发 HTTP 请求时用到 openai 客户端库，
工具调用使用模型原生的 function calling。

【二、仓库地址】
https://github.com/moon976/mini-coding-agent

【三、如何运行】
Python 3.10+，依赖见 requirements.txt。
  1. pip install -r requirements.txt
  2. 复制 .env.example 为 .env，填入 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL
     （默认 DeepSeek，任何 OpenAI 兼容网关均可切换）
  3. 无需 key 先跑通：python main.py --mock "修好 hello.py"
     （内置假模型，按剧本回放，不联网）
  4. 真实任务：python main.py "给 hello.py 的 add 写单元测试并跑通"
  5. 网页界面：python main.py --web（浏览器打开 127.0.0.1:8000）

【四、特色功能】
· 自研主循环：问模型 → 解析工具调用 → 本地执行 → 结果回写 → 再问
· 六个工具：列目录、读文件、精确编辑、写文件、执行命令、搜索文本
· 精确编辑 edit_file：只替换要改的一段，不整文件重写；找不到原文或
  匹配到多处即拒绝执行，避免改错地方
· 上下文管理：超预算时按「整组」压缩，不产生孤儿消息，并提示模型
  最初的任务以防失忆
· 三层错误处理：工具失败转成文字交回模型让它自改方案；网络失败按
  1s/2s/4s 退避重试；401、404 这类不重试，直接给可操作的中文提示
· 双重终止：模型不再调工具即结束；达最大步数强制停止，防死循环烧钱
· 安全三道闸：黑名单直接拒绝；rm、git reset --hard 等高危命令人工
  确认；文件操作锁在 workspace/ 内
· 假模型自测：三个剧本（正常完成/失败换方案/打转不停），无 key 也能
  演示自我修复与步数兜底
· token 统计：结束显示请求数、重试数与输入输出 token
· 网页界面：主循环把每一步 emit 成事件，命令行打印成文字、网页渲染
  成卡片，共用同一份循环逻辑，未另写一套；高危命令在网页上弹窗确认

【五、几处关键取舍】
1. 工具失败不抛异常，转成文字交回模型。程序崩了模型就没机会改正；
   错误回到对话里它才能换办法重试。这是 agent 与脚本的本质区别。
2. 压缩必须整组删除 assistant 及其后的 tool 消息，只删一半会留下没有
   对应调用的工具消息，接口直接报错。
3. 安全默认值取保守项：拿不到确认回答时一律当作"不执行"。
4. 危险命令判断宁可误报不可漏报——漏报文件找不回来，误报只是多按
   一次 y；但 python xxx.py 这类必须直接放行，否则每步都问没法干活。

【六、其它说明】
· API key 仅从 .env 或环境变量读取，未入库，也未出现在视频中。
· 演示任务选"写单元测试并跑通"：它会先失败，再判断是测试写错还是
  源码写错，完整展示失败—定位—修正—复验。
· 尚未完成：会话持久化；长任务分级摘要（现为丢弃最早的整组消息）。
