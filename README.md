# mini-coding-agent：从零手写的最小编程智能体

不依赖任何 agent 框架，自己实现「模型要工具 → 本地执行 → 结果回写 → 再问模型」这个循环。

## 快速开始（不需要 API key）

```bash
python main.py --mock "工作目录里的 hello.py 有个 bug，请找出来修好"
```

`--mock` 用的是内置假模型：它按写好的剧本念台词，不联网。**这一步验证的是主循环本身对不对**，跟模型好不好无关——模型是变量，先把它钉死。

其它两个剧本：

```bash
python main.py --mock --script retry "修好 hello.py"        # 演示失败后换方案重试
python main.py --mock --script loop --max-steps 3 "修好 hello.py"  # 演示步数上限这个刹车
```

## 接上真实模型

1. 复制 `.env.example` 为 `.env`，填入 `LLM_API_KEY`（DeepSeek / 任意 OpenAI 兼容网关均可）。
2. `python main.py "你的任务"`

首次运行需要 `pip install openai`。`.env` 已在 `.gitignore` 中，不会进仓库。
**key 一旦泄露到仓库或视频里，立刻去厂商后台作废重发。**

## 网页界面

双击 `启动网页版.bat` 即可（会自动打开浏览器）；或者：

```bash
python main.py --web          # 浏览器自动打开 http://127.0.0.1:8000
python main.py --web --port 9000
```

三栏布局：中间是对话流（模型的思考和工具调用渲染成可折叠卡片），左边是 workspace 文件树，右边是文件预览——agent 改完文件会自动刷新。

**思考过程默认折叠**：任务运行时步骤实时滚动展示；正常结束后，全部过程收进一个「思考过程（N 步 · 点击展开）」的折叠区，画面上只留最终回答。出错或手动停止时不折叠——那种时候你正需要看细节。

网页**没有另写一个循环**：主循环把每一步 emit 成事件，命令行打印成文字，网页渲染成卡片，两者共用同一份逻辑。

终端里危险命令靠 `input()` 等人敲 y；网页里没人敲键盘，于是改成 agent 线程发一个 confirm 事件后阻塞在队列上，等你点「允许/拒绝」。另外加了第三个终止条件：随时能点停止。

## 工具

| 工具 | 作用 |
|---|---|
| list_dir | 列目录（自动过滤 `__pycache__` 等噪音） |
| read_file | 读文件，带行号 |
| edit_file | **精确替换**：只改要改的那一段，找不到或匹配到多处就拒绝 |
| write_file | 整文件写入（新建文件用） |
| run_command | 执行命令，返回 stdout / stderr / 退出码，带超时 |
| search_text | 文本搜索（简化 grep） |

## 四条核心设计（也是这个项目真正的内容）

1. **工具出错不抛异常，而是把错误变成一段文字回传给模型。**
   程序崩了，模型就再没机会改正；错误回到对话里，它才能换方案重试。这是 agent 和「脚本」的根本区别。
2. **所有文件操作锁死在 `workspace/` 内**（`_safe_path`），越界直接报错。
3. **循环有三个出口**：模型不再要工具（正常结束）、达到最大步数（防死循环烧钱）、用户点停止（人必须随时能叫停）。缺一不可。
4. **命令执行有三道闸门**：黑名单直接拒绝 → 高危命令停下来问人 → 沙盒限定工作目录。

## 安全机制

agent 是在你电脑上真跑命令的，所以「它能不能删我文件」必须想清楚。三道闸门：

| 层级 | 做法 | 例子 |
|---|---|---|
| 黑名单 | 直接拒绝，连问都不问 | `rm -rf /`、`format c:`、`shutdown` |
| 高危确认 | 打印出来，等你按 y | `rm x.py`、`git reset --hard`、`git push --force`、`echo x > a.py` |
| 沙盒 | 工作目录锁死在 `workspace/` | 所有文件读写都过 `_safe_path` |

取舍原则是**宁可误报，不可漏报**：漏报的代价是文件没了，误报只是多按一下 y。
但也不能误伤到没法干活——`python xxx.py`、`python -m unittest` 这类必须直接放行。

确认钩子做成可注入的（`set_confirm_hook`），测试时传个固定返回值就行，不用真按键盘。
**拿不到回答时一律当作「不执行」**：安全相关的默认值，必须选保守的那个。

无人值守时可加 `--yes` 自动放行，但每条都会打印出来——绝不能静默通过，否则事后你根本不知道它删了什么。

```bash
python main.py "删掉 workspace 里所有 .pyc 文件"      # 会停下来问你
python main.py --yes "同样的任务"                      # 自动放行，但会打印
```

## 任务过程落盘（trace）

主循环把每一步 emit 成事件，但打印完就没了。加上 `--trace` 会把完整事件流存成 `traces/*.jsonl`：

```bash
python main.py --trace "修好 hello.py"     # 跑的时候顺手存一份
python main.py --report                    # 读所有记录，打印统计
```

报告长这样：

```
【结局分布】  正常完成 2 个 66.7% / 达到步数上限 1 个 33.3%
【平均每个任务】 步数 4.3 · 工具调用 3.7（失败 0.0）· 请求 4.3 · 上下文压缩 0.0
【token】     输入 10213 · 输出 781 · 输入:输出 ≈ 13:1
```

三个用途：**事后复盘**（失败的任务把事件流重放一遍就知道卡在哪）、
**量化评测**（跑一批任务得出成功率、平均步数、平均 token）、
**回归对比**（改了提示词之后跑同一批任务，看数字有没有变好，而不是凭感觉）。

网页端同样会落盘：顶栏勾选「记录 trace」（默认勾选），每次任务都会在 `traces/` 存一份，
点顶栏的「统计报告」就能看到汇总面板。它和 `--report` 用的是同一份聚合函数
（`trace.report_data()`），所以命令行和网页上的数字不会各说各话。

> 注意：假模型任务的 token 全是 0，统计里的 token 一栏只算真实模型任务。
> 想攒出能写进简历的数字，用真模型跑，并且**别把假模型的演示记录混在里面**
> （`traces/` 不进仓库，删掉重跑即可）。

**跑哪批任务？** 见 `BENCHMARK.md`：10 个真实任务（每个对应一种能力，附预期步数与通过标准）
+ 2 个安全演示（该被拒绝的那种，不计入统计）。照着发一遍，就能拿到成功率、
平均步数、平均 token 三个数字。

## 上下文预算：为什么按 token 而不是字符

原来用字符数当预算，这对中文是**系统性失真**的：英文约 4 字符 = 1 token，
中文常常 1 个字就要 1 个 token。同一份预算，装英文能装 4 倍的量，装中文只能装 1 倍 ——
结果是中文任务**过早压缩**（白白丢信息），英文任务**过晚压缩**（请求直接超限失败）。

精确算 token 需要分词库（tiktoken），而我们要保持零第三方依赖。所以 `tokens.py` 里
写了个**自校准**的估算器：起点是个粗略猜测（2.5 字符/token），
每次请求后用模型返回的真实 `prompt_tokens` 回喂校准。

关键在于**用差分而不是直接除** —— 因为 `prompt_tokens` 里不只有对话历史，
还有一份固定的工具说明书开销（6 个工具的 JSON schema，几百 token）。直接拿总量除，
会把这份固定开销算进单价里，越算越离谱。做两次差分，常数项就被消掉了：

```
第 N 次：  tokens = schema + chars / 单价
第 N+1 次：tokens = schema + chars' / 单价
两式相减： Δtokens = Δchars / 单价    →    单价 = Δchars / Δtokens
```

`tests/test_tokens.py` 里有一条测试专门钉住这一点（还配了一条对照试验，
证明"不做差分"的方案确实算错，免得日后被改回去）。

## 已知的取舍（主动说明，别等别人问）

- **黑名单是「文本特征匹配」，不是安全边界。** 实测 `echo 'shutdown now' > a.txt` 会被误判成
  关机命令 —— 误报的代价只是换个写法，漏报的代价是文件没了，所以选了「宁可误报不可漏报」。
  更可靠的隔离要靠容器 / 受限用户，这个项目没做。
- **`shutdown` 放在第一层（直接拒绝）偏严。** 它是可恢复的（重启即可），
  严格说更适合降级到第二层「弹出来问人」。
- **停止按钮只在任务运行中生效。** `run()` 开头会清掉停止标记，
  否则点了停止之后下一个任务会一启动就秒退。
- **假模型也有 `usage` 计数（但不消耗真 token）**，为的是让统计代码不用区分真假客户端。
- **含换行的命令一律拒绝，而不是交给 shell。** 因为 shell 只会执行第一行，
  其余被**静默丢弃**且退出码仍是 0（实测 `echo a↵echo b` 只输出 `a`，退出码 0；
  `python -c "↵print(1)↵"` 完全没有输出）。这种"假成功"比报错更危险：
  报错还能触发模型换方案，"成功但没输出"会让它基于错误结论继续推理。
  代价是模型想跑多行脚本时，得先 `write_file` 写成文件再执行，多一步。
  这是通过 trace 复盘 T10 那条任务时发现的（详见 `BENCHMARK.md`）。
